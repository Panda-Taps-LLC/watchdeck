## [Unreleased]

The first release of watchdeck: an observatory and control plane over Claude Code's own safety settings, plus an OS sandbox where Claude Code has none. Local, private, one binary.

### Added

- The dashboard (`watchdeck` opens it): Home with one sentence on whether you are protected, Needs you (add the suggested rule, acknowledge or dismiss, each with undo), Live now and Recent decisions; Sessions with every session on this machine, a live lane map and a per-session map that names who decided each call (Claude Code's deny rules, its auto check, you, watchdeck, the sandbox); Rules with everything that limits an agent in five groups, strongest first, recommended rules with Add, Add all and Decline, and an Add rule sheet that previews the rule and the file it writes before writing it; Settings. Loopback only, behind a token, no telemetry; every on-screen sentence lives in one copy module under a lint.
- The hook: skill scripts, named commands and MCP servers run in their own OS sandbox (Seatbelt on macOS, bubblewrap on Linux); your own Claude Code Bash deny and ask rules are honoured against the original command before any rewrite; every auto-mode denial is recorded; a watchdeck command typed by the model always asks.
- The rules control plane: twelve recommended Claude Code Read and Edit rules offered at `setup` after one yes/no, written to your settings with a backup and an ownership ledger; `watchdeck rules list|add|remove|set|recommended|reconcile|grant`; `watchdeck inbox` and `inbox resolve <id> add|ack|dismiss|undo`.
- The CLI's six documented commands (`watchdeck`, `setup`, `status`, `rules`, `doctor`, `uninstall`) and `watchdeck advanced` for the rest; `watchdeck uninstall` removes everything it wrote in one confirmed step.
- The activity log, the session index over every Claude Code transcript (read-only, local), session lifecycle records, and the Claude Code plugin (a band above the prompt, `/watchdeck:open`, `/watchdeck:status`).
- Developer tools: fixture homes with hundreds of synthetic sessions (`scripts/fixture-home.sh --many N --live K --installed`), a walkthrough with a keyboard pass, axe and screenshots (`scripts/walk.sh`, dispatchable by hand as a GitHub workflow), `scripts/screenshots.sh`, `scripts/demo-gif.sh`, `scripts/prove-native-deny.sh` and `scripts/measure-hook.sh`. `scripts/test-install.sh` and `scripts/measure-hook.sh` also run in CI (the `install` and `latency` jobs); the rest never do.
- `watchdeck doctor --prove`: runs the hook your settings register against a built-in canary in a throwaway HOME and reports five checks (registration, rewrite, sandbox, read rule, shadow); exits 1 when any fails.
- Shadow mode for watchdeck's own rules: `mode: shadow` in `overrides.yaml` (`watchdeck rules shadow on|off`) records what every pack, rule and gate would have done (`would: deny|ask`) without blocking or asking; Claude Code's own rules and the OS sandbox are unaffected. Home and the header read "Observing only", the Rules page shows a banner, `doctor` and `status` warn; the map labels observed calls.
- `scripts/measure-hook.sh` gains `CHECK=1`: exit 2 when the no-opinion median or p95 is over the +1/+2 ms budget (the CI `latency` job uses it).
- CI: staticcheck and govulncheck for both OS targets, the installer test on macOS and Linux, the plugin's strict validation and mod tests under Claude Code 2.1.304, a 20 s run of each fuzz target, an advisory hook-latency check on macOS and a two-runner reproducibility check of the snapshot binaries.
- Release pipeline: reproducible builds (`-trimpath`, an empty build id, commit-time file times), one SPDX SBOM per archive, a keyless cosign bundle on `checksums.txt` and a GitHub build-provenance attestation for every file in it; signing and attestation run only from the public repository. Guard tests pin the workflows' pins, permissions, gating and the goreleaser flags.
- Docs: SECURITY.md rewritten for the observatory and the Rules page, with "What we do not stop" and "Verify a release"; README "Verify a release"; CONTRIBUTING "Releasing"; DESIGN section 6 refreshed and section 12 added.
- CI: a `secrets` job runs gitleaks 8.30.1 (pinned by version and sha256) over the whole history with `--redact`; `.gitleaks.toml` allowlists the fixtures.
- `scripts/install.sh --verify` (or `WATCHDECK_VERIFY=1`): verify the archive's build provenance with the GitHub CLI, or the cosign bundle on `checksums.txt`, before installing; nothing is installed when that fails; tested against stubs (`scripts/test-install.sh`, 14 cases) until the first public release.
- `watchdeck rules explain`: what the hook would answer for one call (a command, a read, an edit, a write, a URL, an MCP tool or a skill) and by which rule, with exit codes 0 allow, 1 deny, 2 ask, and `--expect` for CI (under shadow mode it also names on stderr what enforce mode would do); it records nothing.
- `docs/DENIED.md` and `scripts/denied-study.sh`: a recorded study of what Opus, Sonnet and Haiku do when a Claude Code rule, a watchdeck rule or the sandbox is set to refuse a call, run headless with Bash on; the classifier `scripts/denied-study.py` has a self-test. 18 sessions on 2026-10-20 and 2026-10-21 leaked nothing; three WebFetch calls went around a refused `curl` unrefused.
- The dashboard's rule stats and try routes: `GET /api/rules/stats` counts how often each pack rule, rule of yours and Claude Code Bash rule fired, and when it last did, from the activity log; `POST /api/rules/try` answers what the hook would do for one command, read, edit, write, URL, MCP tool or skill, by your saved rules, as `watchdeck rules explain --json` prints it. Both record nothing and change no policy or settings file.
- Leak watch: the session index scans tool results, model replies and tool inputs (never typed prompts) for eight kinds of secret-shaped strings (AWS key ids and secret keys, private keys, GitHub, Slack, Anthropic, OpenAI and Stripe live keys), stores where each was seen but never the text, and lists each finding in Needs you, also with the activity log off; off under `--no-transcripts`. The index format moves to version 4, so the first run rebuilds it once.
- Rules that cover every route: `watchdeck rules add --everywhere` (and `everywhere` on the dashboard's add) writes one intent as every rule that reaches it. A path gets Claude Code's Read and Edit rules, a Grep and Glob rule and a shell-command rule. A domain gets Claude Code's WebFetch rule, the sandbox's denied domains (designed, not tested against Claude Code), a WebFetch rule and a rule for network programs in shell commands. A command gets its hook twin. `watchdeck rules remove --intent <id>` and `remove_intent` on `POST /api/rules` remove them together, while `rules remove <id>` still removes one. Skill scripts are not covered.
- Temporary allows: pause one of watchdeck's own rules for an hour, eight hours or one session (`watchdeck rules pause <id> --for 1h|8h|session=<id>`, `rules pause --list`, `rules resume <id|all>`), and widen a skill's sandbox grant for up to eight hours (`watchdeck allow <skill> --network all --for 1h`). Entries live in a `temporary:` list in `overrides.yaml` and end by themselves; a paused rule blocks and asks nothing and is still recorded, a timed grant still asks before the script runs (even for a skill set to auto-allow), and Claude Code's own rules cannot be paused. `GET /api/rules` lists them and `POST /api/rules` ends one.
- Home's Needs you (as of Plan 08; the buttons named here folded into the decision sheet on 2026-10-28, see Changed): a secret seen in a transcript is a row of its own ("Secret seen", where it appeared, a link to the call in its timeline, and, for a file the agent read, wrote or edited, a rule that blocks reading that file); a path or domain fix has a second button, "…and every other route", whose confirm lists every rule it writes; and an item that only watchdeck's own rules stopped has "Allow for this session" and "Allow for an hour" (a skill's request: for an hour), which pause those rules or widen the skill's grant, ask first and can be undone. Claude Code's own rules, auto mode and a person's no cannot be allowed this way.
- The Rules page: a caption saying what the rule counts cover and a "fired N · last <ago>" ("matched N …, noted only" when the newest hit was paused or log-only) or "never fired" chip on built-in rules, your own rules and Claude Code Bash block or ask rules; a "Try a call" box before Add rule that shows what your saved rules answer for one call, with links to the matched rows; a "part of" chip on rules added to cover every route, whose Remove offers "Remove all N" or "Only this rule"; a Temporary notice with "End now"; and "Cover every route", on by default for a path or a domain in the Add sheet.
- Plan 08's fixtures, walk and docs: every fixture home holds a session with a fake Slack-shaped token in a read and a reply, three asks by a rule of the person's, one deny by a Claude Code Bash rule, a one-hour pause and, built with a binary, one rule for every route; the walk checks Home's leak row and allow buttons and the Rules page's "part of" chip, Temporary notice and rule counts; seven screenshots, `home-leak` and `rules-try` new; `scripts/denied-study.sh --intent-host` and `--leak`, with two DENIED.md addenda from four sessions on 2026-10-25 UTC (the hook refused every curl and no model tried WebFetch; leak watch listed a token Haiku read and quoted), and the `webfetch-deny` scenario with `--no-web-hook` and `--real-transcript`, from five more sessions the same day (every WebFetch refused, by watchdeck's rule or, with the hook off WebFetch, Claude Code's own; leak watch found the token in Claude Code's own transcript file); GUIDE sections for leak watch, rules for every route, allowing for a while, and rule counts and the try box.
- An inbox fix can be added for just the project the call happened in (2026-10-28), from the decision sheet's Where popup: `POST /api/needs/{id}` takes `scope: project`, `GET /api/needs` names each fix's project files (only for a git checkout), and an undo finds the project's settings file from anywhere, including `watchdeck inbox resolve <id> undo` from another directory.

### Changed

- The dashboard's look (2026-10-26): the Mac-native family picked from the design canvas. The top bar is now a sidebar with a tinted rounded-square icon per section (the Settings gear shows its word) and the protection line at its foot; pages use the system font at 13px, grouped white cells with hairline borders and no shadows, 30px controls and a 30x18 switch; confirmations drop from the top edge as a sheet. On the Rules page the facts under each rule read as one quiet line instead of chips. On Home the sentence is a status cell, each item has one filled button and text for the rest, and Live now is a list of rows. Below 760px the sidebar wraps back into a bar. Sessions shows Live now as the same rows and its filters lose their pill shape; Settings stacks its file cards as cells. The switches are real switches (`role="switch"`). Ids, classes, routes, copy and the keyboard order are unchanged; the embedded Space Grotesk and JetBrains Mono stayed in the font stacks behind the system fonts (removed two days later, below). Styles, markup and ARIA only; no Go changed.
- The tree is staticcheck-clean (v0.8.2, both OS targets); no behaviour change.
- Home's Needs you (2026-10-28): each item is one sentence ("Claude Code's auto check stopped Bash · curl in api.", "A watchdeck rule caught …", "The sandbox refused …", "The skill … asked for more than it has", "You said no to …", "Slack token appeared in the result of Read · …"), one muted line (who decided, when, the reason) and one filled button that names the default choice ("Keep stopping it…", "Ask me next time…", "Let it through…", "Block reading it…", "Acknowledge…") and opens a decision sheet. The sheet, the design canvas's A2 board, has the For (Always, This session, An hour), Rule (each suggested rule, "by every route" for the one that covers every route) and Where (Everywhere, Only in <project>) popups, names the file it writes and its backup, carries "Just acknowledge" and "Don't show this again" as text, links a skill request to its drill-in and a secret seen to its call in the timeline, and writes on its one filled button; the row then fades and Undo follows as before. The six inline buttons per row are gone.

### Removed

- The embedded Space Grotesk and JetBrains Mono (2026-10-28; fallbacks behind the system fonts since the Mac-native restyle): the dashboard loads no font file, `/fonts/*` is gone and the page's CSP drops `font-src`.
